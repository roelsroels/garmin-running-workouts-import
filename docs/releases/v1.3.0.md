# Garmin Running Workouts Import 1.3.0

Version 1.3.0 adds native Claude explanations and an Apple Calendar-compatible export, with clearer credential handling
and deployment identification. The planner still works without an LLM, and explanations cannot alter workouts.

## Highlights

- **Claude (Anthropic)** is available in both web and interactive CLI settings, using the native Messages API.
  Haiku 4.5 is the default; the model ID is editable. Existing OpenAI-compatible providers remain supported.
- **Masked API-key entry** in web Settings keeps an entered key in server memory for that browser session, usable for
  up to one hour or until the service restarts. A forget-key option and environment-variable alternative are included.
  Keys are not written to SQLite, browser cookies, or application files.
- **Add to calendar (.ics)** in the full calendar downloads today's and future scheduled runs from the active plan,
  including workout names and instructions. Completed, missed, skipped, and past runs are excluded.
- **Version and branch in the footer** make it easier to identify the running deployment.

## Using the new features

### Claude explanations

Open **Settings → Optional LLM explanation**, select **Claude (Anthropic)**, enter an Anthropic API key, and save.
Open a plan proposal and click **Explain this proposal** when you want the explanation.

Saving makes no API request. Requesting an explanation sends goal details (including free-text constraints), running
summaries, and the plan rationale to the provider and may incur API charges. Garmin credentials and original FIT files
are not sent. Provider access is checked only when an explanation is requested; the model does not edit the schedule.

For persistent access, configure `ANTHROPIC_API_KEY` in the protected web-service environment file and restart the
service. Leave the masked field blank. Temporary web keys are browser-scoped and assume the documented single-worker
deployment; environment keys work across workers. CLI-entered keys are kept only until the CLI exits.

### Calendar export

Open **Calendar → Add to calendar (.ics)**, then open the downloaded file in Apple Calendar or another calendar app.
Runs are all-day events marked as not busy because the planner stores dates, not start times.

This is a one-time import, not a subscription. Later replanning does not update or remove previously imported events.
Event IDs are stable within the same plan, but re-import behavior varies by calendar app. A separate calendar makes
it easier to remove superseded future events before importing a replacement block. The link is hidden when no upcoming
scheduled runs remain. Downloading uses saved local data and makes no Garmin request.

## Security and compatibility

- Native Claude requests are restricted to the official Anthropic API endpoint.
- API credentials are not forwarded through redirects, and provider error bodies are not displayed.
- Failed LLM requests are not automatically retried; authentication, quota, model, and connection errors remain explicit.
- Remote OpenAI-compatible endpoints must use HTTPS. Plain HTTP remains supported on loopback for local services.
- The Settings page uses a plain support link instead of loading the third-party footer widget on credential forms.
- Python 3.12 through 3.14; no new runtime dependencies or database schema changes.
- This remains a running-only, single-runner application, not a multi-user account service. Keep the web interface
  behind the documented authenticated TLS reverse proxy.
- Garmin Connect uses private, unpublished endpoints and may require maintenance when Garmin changes them.

## Upgrade

To keep an existing deployment on `main`:

```shell
git switch main
git pull --ff-only origin main
uv sync --no-dev --locked
sudo systemctl restart garmin-running-workouts-web.service
```

Use your actual service name if it differs from the supplied example. The service restart applies to Linux web
deployments; CLI-only installations do not need it. Preserve any local changes before switching branches or pulling.

To pin exactly this release instead:

```shell
git fetch origin --tags
git switch --detach v1.3.0
uv sync --no-dev --locked
```

Restart the web service after switching versions. A pinned checkout is detached; switch back to `main` before using
normal branch-based updates. Existing goals, plans, progress, FIT files, and Garmin tokens in the configured data
directory are retained. No Garmin re-import or database copy is required.
