# Garmin Running Workouts Import 1.2.1

Version 1.2.1 makes slower Garmin operations visibly responsive. A running-puppet wait screen now confirms that the
request is still active while Garmin creates workouts, reads activities, inspects the calendar, or updates a schedule.

## Highlights

- A lightweight inline runner animates over the current page during supported slow operations.
- Every action displays specific progress text, such as applying a schedule, refreshing completed runs, or checking
  Garmin's calendar.
- The short appearance delay avoids flashing the wait screen for immediately completed requests.
- The overlay prevents accidental duplicate submissions while retaining enough of the page to preserve context.
- Forms expose their busy state to assistive technology through live status messaging and `aria-busy`.
- Reduced-motion preferences keep the runner visible without limb or pulse animation.
- Returning to a cached page clears any previous waiting state automatically.

## Covered operations

- Creating or reassessing a training proposal.
- Refreshing completed Garmin activities.
- Inspecting, applying, or cleaning a Garmin schedule.
- Scheduling a one-off workout.
- Connecting and testing a Garmin session.
- Requesting the optional plain-language proposal explanation.

## Upgrade

From an existing checkout:

```shell
git fetch --tags
git checkout v1.2.1
uv sync --no-dev --locked
```

Existing goals, plans, progress, downloaded FIT evidence, and Garmin tokens remain in
`~/.garmin-running-workouts/`. Version 1.2.1 does not require a database migration. Restart the web service after
upgrading a server deployment.

## Install from the tag

```shell
git clone https://github.com/roelsroels/garmin-running-workouts-import.git
cd garmin-running-workouts-import
git checkout v1.2.1
uv sync --dev --locked
```

## Compatibility and scope

- Python 3.12 through 3.14.
- The project is intentionally running-only.
- Garmin Connect access uses private, unpublished endpoints and can require maintenance when Garmin changes them.

## Verification

The release candidate passes the complete pytest suite, Ruff lint and formatting checks, locked-dependency
validation, package builds, and interactive desktop-browser validation of the animated wait state.
