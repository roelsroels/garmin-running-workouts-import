# Garmin Running Workouts Import 1.5.2

Version 1.5.2 corrects progress accounting across training-block boundaries and adds a safe one-time cleanup for
obsolete Garmin Connect workout templates left behind during an earlier rollover.

## Highlights

- **Accurate current-block counters:** a newly generated block starts with its own completed, missed, and remaining
  totals. Results from the finished predecessor no longer inflate the current block's progress bar.
- **Adaptation history is preserved:** when the remaining workouts inside a block are reassessed, completed and missed
  workouts from earlier revisions of that same block still count toward its progress.
- **One-time cleanup for existing deployments:** open **Garmin cleanup**, select **Inspect previous-block workouts**,
  review the exact template names, confirm the deletion, and select **Delete obsolete templates**.
- **Complete finished-block coverage:** cleanup includes every revision of the prior block, including templates for
  workouts completed before a mid-block adaptation.
- **Protected evidence and history:** active-block templates, reused workout names, completed activities, FIT files,
  execution scores, recorded distances, and past calendar history are never deleted by the one-time action.

The cleanup is idempotent. Once it has succeeded, inspecting again reports zero obsolete templates. New future block
rollovers perform the same complete cleanup automatically after the replacement schedule uploads successfully.

## Upgrade

For an existing deployment following main:

~~~shell
git switch main
git pull --ff-only origin main
uv sync --no-dev --locked
sudo systemctl restart garmin-running-workouts-web.service
~~~

Use your actual service name if it differs from the supplied example. CLI-only installations do not need a service
restart.

To pin exactly this release instead:

~~~shell
git fetch origin --tags
git switch --detach v1.5.2
uv sync --no-dev --locked
~~~

Restart the web service after switching versions. A pinned checkout is detached; switch back to main before using
normal branch-based updates.

## Compatibility and verification

- No database migration and no new runtime dependencies.
- Existing goals, plans, progress, FIT files, credentials, activities, and calendar history are retained.
- CLI commands and YAML formats remain compatible. Python 3.12 through 3.14 are supported.
- Verified with the complete 243-test Python suite, eight JavaScript theme tests, Ruff lint and formatting checks,
  locked-dependency validation, package builds, and an installed-wheel smoke test.

Downloads include a Python wheel, source distribution, and SHA256SUMS. GitHub also provides source archives of the
tag.
