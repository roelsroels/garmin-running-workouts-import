# Garmin Running Workouts Import 0.9.0

Version 0.9.0 is the first tagged release of the running-only fork. It combines the original readable
workout definitions with a goal-driven planner, FIT-based progress assessment, safe Garmin schedule
management, and matching CLI and web workflows.

## Highlights

- Create a running goal and a dated training block through the interactive CLI or web interface.
- Review every proposed workout before anything is uploaded or scheduled in Garmin Connect.
- Fetch completed Garmin activities and original FIT files, then use the decoded evidence to assess progress.
- Adapt only the remaining portion of an active block, with explicit approval before replacement.
- Supply heart-rate caps, BPM ranges, or Garmin zones for each workout phase without editing YAML.
- Detect existing Garmin calendar conflicts and retire obsolete entries without touching completed activities.
- Use the deterministic planner without an LLM; an optional LLM may explain proposals but cannot silently change them.

## Installation

Python 3.12 through 3.14 and [uv](https://docs.astral.sh/uv/) are required.

```shell
git clone https://github.com/OWNER/garmin-running-workouts-import.git
cd garmin-running-workouts-import
git checkout v0.9.0
uv sync --dev --locked
./garmin-workouts --help
```

Replace `OWNER` with the repository owner. For a runtime-only server installation, use
`uv sync --no-dev --locked` instead.

## Upgrading an existing checkout

Back up the portable application data directory before a production upgrade, then switch the checkout to the tag:

```shell
cp -a ~/.garmin-running-workouts ~/.garmin-running-workouts.backup
git fetch --tags
git checkout v0.9.0
uv sync --no-dev --locked
```

Restart the configured web service after upgrading. Existing state remains under
`~/.garmin-running-workouts/`; it is not part of the Git checkout.

## Compatibility and operational notes

- The project is running-only. Cycling workout support remains in the upstream project.
- Garmin Connect access uses private, unpublished endpoints. Garmin changes can require client maintenance.
- The included web deployment is intended for a single trusted user and must be placed behind TLS and authentication.
- Deployment examples are generic templates; paths, service users, hostnames, and certificate locations must be adapted.
- Existing YAML workflows remain available alongside the interactive CLI and web interface.
- Local state and tokens are architecture-independent files and can be migrated between hosts while the application is stopped.

## Planning scope

The planner produces conservative, evidence-informed running suggestions from a declared goal, availability,
recent training history, and optional user-supplied limits. Its rules are deterministic and reviewable. It does not
diagnose, provide medical clearance, derive clinical heart-rate zones, or replace an appropriately qualified coach
or health professional. When evidence is sparse, the planner lowers confidence and avoids narrow performance targets.

## Known limitations

- Garmin authentication may trigger rate limiting even with local pacing and cooldown controls.
- FIT files cannot capture important context such as pain, illness, perceived effort, sleep, or the reason a workout changed.
- Garmin-derived metrics use proprietary algorithms and are treated as supporting context rather than ground truth.
- Multi-user web hosting and unattended automatic plan replacement are outside the scope of this release.
